Trace architecture

One Go binary · local history per Git worktree · optional companions and hosted sync
Package and process boundaries
LayerImplementation
Entry pointscmd/trace → internal/cli; hooks bypass Cobra initialization.
Captureadapters/*, event, redact, daemon, watch. Hooks, embedded JS/TS/Python bridges, and optional transcript/database readers normalize agent activity.
History engineengine coordinates sessions, turns, edit attribution, manifests, keyframes, safety snapshots, and retention. structure adds optional Tree-sitter classification.
Persistencestore: SQLite WAL, migrations and update records. manifest: path → hash + mode. blob: SHA-256, zstd, content-defined chunks.
Queries and recoveryhistorysearch, why, restore, export, gitx; CLI commands open the same local engine rather than querying a daemon API.
Agent contextmcp: eight read-only tools over stdio. companions: bounded JSON subprocess calls to separate trace-brain and trace-graph executables.
Cloud boundarysyncclient: pairing/OAuth, OS credential store, acknowledged upload cursors, chunk transfer and recovery. Hosted internals belong to the separate trace-platform repository.
ExtensionsExecutables named trace-* on PATH become subcommands. repo, id and textutil provide shared utilities.
